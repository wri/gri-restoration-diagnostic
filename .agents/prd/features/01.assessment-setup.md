## Feature 1: Assessment Setup Flow

### 1. Overview

The **Assessment Setup Flow** allows restoration coordinators to initialize a new diagnostic assessment by providing lead and region metadata. Upon completion, the system generates a unique assessment URL and password for secure access.

**Related MVP Scope:** Section 4.2 of main PRD  
**Database Tables:** `lead`, `assessments`, `region`  
**Timeline:** Week 2 (Foundation phase)

---

### 2. User Stories

1. **Primary Flow**  
   As a restoration coordinator  
   I need to create a new assessment with my contact details and region information  
   So I can begin a structured diagnostic workshop.

2. **Access After Setup**  
   As a coordinator who completed setup  
   I can start the assessment immediately without re-entering credentials  
   So I maintain workflow continuity.

3. **Return Access**  
   As a coordinator returning to a saved assessment URL  
   I must authenticate with the password  
   So unauthorized users cannot access workshop data.

#### 3.2 Form Fields

**Section 1: About You**

| Field | Type | Required | Validation | Maps to DB |
|-------|------|----------|------------|-----------|
| Title | Select | No | Enum: Mr/Mrs/Ms/Miss/Dr/Prof | `lead.job_title` |
| Full Name | Text | Yes | Min 2 chars (trimmed) | `lead.name` |
| Email | Email | Yes | Valid email format, lowercase | `lead.email` |
| Organization | Text | No | - | `lead.organization` |

**Section 2: Geography**

| Field | Type | Required | Validation | Maps to DB |
|-------|------|----------|------------|-----------|
| Region Name | Text | Yes | Min 2 chars (trimmed) | `region.region_name` |
| Geography Type | Select | Yes | Predefined enum | `region.geography_type` |

---

#### 3.3 Validation Behavior

**Client-Side:**
- Submit button always enabled
- On click:
  1. Validate required fields
  2. Check email format (HTML5 + regex)
  3. Validate URL format (if GIS provided)
  4. Show inline errors per field
  5. Prevent submission if invalid

**Server-Side (API Route):**
- Re-validate all client rules
- Return 400 with field-specific errors if invalid
- Proceed to creation only if valid

---

#### 3.4 Submission Flow

**On Valid Submission:**

1. **POST `/api/assessments/setup`**

**Request Body:**
```json
{
  "jobtitle": "Dr.",
  "name": "Jane Doe",
  "email": "jane.doe@example.org",
  "organization": "WRI Brazil",
  "regionName": "Amazon Basin",
  "geographyType": "Watershed",
  "country": "Brazil",
  "subRegion": "Pará",
  "ecosystems": ["Tropical Forest", "Wetland"]
}
```

**Server Transaction:**
1. Begin DB transaction
2. Create `lead` record → get `lead_id`
3. Generate:
   - `assessment_id` (UUID)
   - Random 10-char password
   - `password_encrypted` (bcrypt hash)
4. Create `assessments` record with:
   - `diagnostic_id` (default to latest version)
   - `diagnostic_year` (current year)
   - `project_type` = 'other'
   - `creation_date` = now()
5. Create `region` record → link to `assessment_id`
6. Commit transaction

**Response (201):**
```json
{
  "assessmentUrl": "/assessments/{assessment_id}",
  "password": "xK9mP2vN8q",
  "assessmentId": "uuid-here"
}
```

---

#### 3.5 Success Modal

**Trigger:** Successful 201 response

**Modal Content (WRI DS Blocking Modal):**
- Title: "Assessment Created"
- Display:
  - Assessment URL (copyable text)
  - Password (copyable text)
  - Instruction: "Save these credentials before continuing"
- Checkbox: "I've saved the link and password"
- Primary button: "Start Assessment" (disabled until checkbox checked)
- Secondary action: "Close" (optional)

**Behavior:**
- "Start Assessment" → navigate to `/assessments/{assessment_id}` with one-time bypass token
- "Close" → dismiss modal, user remains on setup page
- Closing tab → assessment persists, accessible via saved URL + password

**Design Reference:** https://wri.github.io/wri-design-systems/?path=/story/containers-modal--blocking

### 4. Assessment Access Patterns

#### 4.1 Direct Access (Post-Setup)

**Route:** `/assessments/{assessment_id}?token={one-time-token}`

**Logic:**
- Validate token exists in session/cache
- If valid: grant access, consume token, establish session
- If invalid/missing: redirect to password prompt

#### 4.2 Returning Access

**Route:** `/assessments/{assessment_id}`

**Password Prompt UI:**
- Label: "Enter assessment password"
- Input: password field
- Button: "Access Assessment"

**Validation:**
- POST `/api/assessments/{assessment_id}/login`
- Body: `{ "password": "user-input" }`
- Compare bcrypt hash
- Response:
  - 200 → set session cookie, redirect to assessment
  - 401 → show error "Incorrect password"

### 5. Technical Implementation

#### 5.1 Frontend (Next.js)


**State Management:**
- React Hook Form for validation
- Context API for one-time token passing

**Offline:** Not applicable (requires server for creation)

---

#### 5.2 Backend (API Routes)

**Endpoint 1: POST `/api/assessments/setup`**

**Implementation:**
```typescript
// Validation
- Check required fields
- Validate email/URL formats

// Transaction
- INSERT INTO lead
- Generate password (crypto.randomBytes)
- Hash password (bcrypt, cost 10)
- INSERT INTO assessments
- INSERT INTO region

// Response
- Return URL + plain password (only time shown)
```

**Endpoint 2: POST `/api/assessments/[id]/login`**

**Implementation:**
```typescript
// Lookup
- SELECT password_encrypted FROM assessments WHERE assessment_id = $1

// Verify
- bcrypt.compare(input, hash)

// Session
- Set httpOnly session cookie (24h expiry)
- Return 200 or 401
```

### 6. Database Schema Mapping

**From DBML Schema:**

```sql
-- lead table (existing)
lead_id VARCHAR PK
job_title TEXT
name TEXT
email TEXT
organization TEXT

-- assessments table (existing)
assessment_id VARCHAR PK
diagnostic_id VARCHAR FK
password_encrypted TEXT
creation_date TEXT
diagnostic_year TEXT (defaults to current year)
project_type project_type_enum (defaults to 'other')
lead_id VARCHAR FK
region_id VARCHAR FK

-- region table (existing)
region_id VARCHAR PK
region_name VARCHAR
geography_type VARCHAR
countries TEXT
sub_region TEXT
ecosystems TEXT (stored as comma-separated or JSON array)
gis_url TEXT (NULL for MVP)
```

**MVP Defaults:**
- `diagnostic_id`: Query latest from `diagnostic` table
- `diagnostic_year`: Extract from current date
- `project_type`: Hardcode to 'other'

3. **Password Complexity:** Is 10-char random alphanumeric sufficient, or require symbols?

### 8. Validation Summary

**Mandatory:**
- `name`, `email`, `regionName`, `geographyType`, `ecosystems` (≥1)

**Format:**
- `email`: RFC 5322 compliant
- `gisUrl`: Valid HTTP/HTTPS (deferred field)

**Enforcement:**
- Client: HTML5 + inline errors
- Server: Re-validate + 400 response
